# 把课程文件夹变成可执行的课堂实验：我们为什么做 XEdu Client

带人工智能实验课的老师，可能都遇到过这样的场景：教师刚讲完任务，学生却还没有真正开始学习。

有人找不到 Jupyter 的启动入口，有人不会选择 Python 环境，有人看到黑色运行窗口就顺手关掉，还有人面对一堆课程文件，不知道下一步应该打开哪一个。教师的时间因此被不断切碎：解释入口、排查环境、寻找文件、重新启动服务。

一节课的注意力，很容易从“这个模型为什么这样判断”，变成“老师，我这里怎么打不开”。

XEdu Client，就是从这样的课堂中断中生长出来的。

> **核心判断：** XEdu Client 不是又一个 AI 工具，也不是简单的 Jupyter 启动器。它要做的是把课程资源、实验入口、运行环境和课堂接入组织起来，让一门 AI 课真正可以进入、可以运行、可以继续。

## 一次课堂中断，暴露了什么问题

最开始，我只是想解决 Jupyter 不好启动的问题。

在实际课堂中，学生往往不需要理解后台进程、端口和命令行。他们只需要进入当前实验，按照任务完成操作。但传统的启动方式会把这些与学习无关的细节直接推给学生：找到环境、打开终端、启动 Jupyter、记住地址，再回到 Notebook。

如果承载服务的黑色窗口被关闭，正在进行的实验还会随之中断。

所以，第一个问题确实是“实验上不起来”。但继续使用后会发现，环境只是最外层的问题。即使 Jupyter 能顺利打开，课程仍然可能是断的：讲解材料在一个文件夹，交互实验在另一个位置，Notebook 又需要重新寻找，素材和辅助代码散落在课程目录里。

学生还没有开始思考人工智能，注意力已经消耗在“我应该打开什么”上。

## 真正需要接起来的，是体验和实践

人工智能中的许多概念，不适合一上来就从代码讲起。

例如神经网络的层数、神经元数量、训练集与测试集、Loss 的变化，如果先让学生在一个可操作的 HTML 页面中调整参数、观察结果，他们更容易形成直观经验。

但体验不能停在“看到了”。学生还需要进入 Jupyter，阅读真正的代码，修改参数，运行模型，并解释结果。

因此，我们更关心的不是“把几个软件放到一起”，而是能不能让学生围绕同一个任务继续前进：

> **先体验现象，再理解过程，最后进入真实代码实践。**

学生不必在每次切换工具时重新寻找文件、回忆任务和建立上下文，注意力可以留在同一个问题上。

这成为 XEdu Client 的第一个产品判断：它不应该只是一个 Jupyter 启动器，而应该是一张能够承接连续学习过程的课堂实验工作台。

## AI Coding 时代，Scratch 为什么仍然重要

过去，我们常把积木编程理解为学习 Python 之前的临时台阶：学生年龄小、不会写代码，所以先拖积木；等能力提高后，再进入文本编程。

AI Coding 正在改变这个判断。代码语法可以由人工智能辅助生成，但学生仍然需要理解问题、拆解流程、观察数据、调整参数、验证结果，并判断模型输出是否可靠。

Scratch 的价值不只是“容易上手”。它把程序结构直接呈现在学生面前，减少拼写、缩进和 API 记忆带来的干扰，让学生先关注流程、逻辑、数据和模型。XEdu Client 当前选择 Scratch 作为持续维护的图形化编程主线，并支持运行 XEdu AI 扩展、查看图片和运行记录。

在不同课程中，教师可以根据教学目标选择不同入口：

| 入口 | 适合承担的任务 |
| --- | --- |
| HTML 交互实验 | 让学生操作、观察并建立直观经验 |
| Scratch 图形化实验 | 让流程、逻辑和 AI 调用过程变得可见 |
| Jupyter / Python 实验 | 让学生进入真实代码，修改、运行并继续探究 |

这三种形态不是三门互相竞争的课，也不意味着每一节课都必须全部使用。它们是同一知识的不同入口：教师根据学习目标选择合适的表征，让不同基础的学生都能进入问题，同时为愿意深入的学生保留通向 Python 的出口。

## 一门课，不应该只是一个 Notebook

一门可执行的人工智能课程，通常不只是一个 `.ipynb` 文件。它可能同时包含：

- 讲解页和任务情境；
- HTML 交互实验；
- Scratch `.sb3` 项目；
- Jupyter Notebook 和 Python 脚本；
- 图片、数据和其他实验素材；
- 教案、导学案和课堂说明。

这些资源如果只是散落在教师电脑里的文件，下一次上课仍然需要重新整理。XEdu Client 用课程目录和课程包把它们组织在同一门课、同一个课节和同一个实验上下文中。

教师可以导入或扫描课程目录，查看课程详情、课节和实验文件，检查资源结构，按需要备份、发布或从远端拉取更新。学生则从课程入口或课堂入口进入当前实验，而不是先在文件夹里猜哪个文件应该打开。

这就是 XEdu Client 与普通文件管理器的区别：它不是只保存文件，而是让课程文件具备可进入的实验结构。

## 一个具体例子：从“搭网络”到“训模型”

仓库中的《运动会上的 AI 裁判：L9 模型训练》，展示了这条路径如何落到一节真实课程里。

学生先通过课程材料理解训练集、测试集和模型训练的基本问题，然后进入 `构建神经网络.html`，调整网络层数和神经元数量，观察结构变化。接着进入 `L9_Part1.ipynb`，读取训练数据，划分训练集和测试集，搭建 MLP，运行训练过程，观察 Loss 曲线和准确率。

这门示例课当前的关键资源包括：

- `构建神经网络.html`：可视化体验网络结构；
- `L9_Part1.ipynb`：进入 Notebook 完成代码实践；
- `training_data.csv`：训练数据；
- `utils.py`：课程辅助代码；
- 教案、学生导学案、课件和模型训练资料：支撑课堂讲解与复盘。

这里最重要的不是一节课用了几个工具，而是学生始终围绕同一个问题前进：先看见结构，再带着理解进入代码，最后用训练结果检验自己的判断。

对教师而言，这也不再是一组临时散发的文件，而是一门可以被导入、检查、运行和继续维护的课程资源。

## 教师如何用它交付一节课

从教师视角看，XEdu Client 的工作流程可以压缩为四件事：

1. **导入课程：**导入课程目录或完整 ZIP 课程包。
2. **检查实验：**确认讲解页、实验文件、素材和 Python 环境可以正常使用。
3. **开启课堂：**选择当前课节并开启课堂，学生从课堂入口进入。
4. **持续更新：**课后备份课程，需要时发布课程或从远端拉取更新。

学生进入课堂后，可以在当前课程中打开 HTML、Scratch 或 Notebook 实验。课堂自动发现失败时，也可以使用教师机的局域网地址加入课堂。

软件负责把资源和入口接起来，教师仍然负责最重要的部分：设计任务、组织讨论、观察学生的理解，并决定什么时候让学生从体验进入实践。

## XEdu Client 到底解决什么问题

如果只看功能列表，XEdu Client 似乎包含了 Jupyter、Scratch、课程资源和课堂模式。但这些功能并不是简单堆叠，它们共同服务于一件事：让 AI 课程从“文件集合”变成“可执行的课堂实验”。

| 对象 | 真正得到的改变 |
| --- | --- |
| 学生 | 少找入口，沿着同一个任务继续做 |
| 教师 | 少切换工具，更稳定地组织课堂 |
| 课程 | 可打包、可迁移、可复用、可持续更新 |

所以，XEdu Client 不是又一个 AI 工具，而是 AI 课程的桌面运行工作台。

## 它不是零配置魔法，也不是万能平台

为了让项目真正进入课堂，我们也需要把边界说清楚。

- 教师版当前使用外置 Python。首次启动仍需选择 Python 3.9 及以上解释器，并确认 Jupyter、`xedu-python` 及课程依赖。
- Python 执行是本机高权限能力，不应被描述为云端沙箱。学校部署时仍需遵守本地软件、账号和网络安全要求。
- 课堂模式依赖学生机与教师机之间的局域网互访。自动发现失败时可以使用教师机地址，跨 VLAN、无线隔离或防火墙限制需要提前确认。
- XEdu Client 不是完整的作业批改、进度分析或 LMS 系统。它负责课程导入、实验运行、课堂分发和资源更新。
- 课程智能创作能力属于 XEdu Teacher Skills，后续会单独撰文介绍，不与 XEdu Client 的产品边界混在一起。

这些边界不是回避问题，而是课堂工具必须具备的诚实：哪些事情已经能够稳定完成，哪些事情仍需要教师、学校环境或其他工具共同配合。

## 现在，可以先跑通一门课

当前教师版支持 Windows x64、Windows 32 位和 macOS Apple Silicon。第一次使用可以按下面的顺序完成最小验证：

1. 安装教师版 XEdu Client。
2. 在“Python”设置中完成选择、确认、测试和保存。
3. 导入一个带有 `course.json` 的完整课程包。
4. 打开一个 HTML、Scratch 或 Notebook 实验并实际运行。
5. 开启课堂，先让一台学生机加入，再让全班进入。

我们真正想验证的，不是这个工作台里装了多少功能，而是它能不能让一节人工智能实验课少一些中断，多一些连续思考；让学生不止“看过人工智能”，而是真正经历从体验、理解到实践的过程；也让教师今天准备的一节课，能够在下一次课堂中继续生长。

> **XEdu Client 想做的，是让人工智能实验课从偶尔成功的展示，变成普通机房里可以稳定发生的学习。**
