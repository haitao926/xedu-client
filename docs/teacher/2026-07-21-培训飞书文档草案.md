# XEdu Client 教师自助操作手册

适用版本：`2.0.0`  
适用对象：第一次使用 XEdu Client、需要独立备课和上课的教师

完成本手册后，你应该能够：安装软件、配置 Python、导入课程、运行 HTML/Scratch/Notebook 实验、开启课堂、同步课程、使用 skill 创建课程，并完成备份和故障处理。

## 0. 使用顺序

请按下面顺序操作，每一步先确认结果再继续：

1. 安装软件并配置 Python。
2. 解锁教师模式并熟悉界面。
3. 导入参考课程并运行一个实验。
4. 开启课堂，让一台学生机加入。
5. 安装 skill，创建一节自己的课。
6. 打包、备份，并同步到 Gitea。

## 1. 先认识 XEdu Client

XEdu Client 是教师的课程工作台：课程资源负责管理课程，Jupyter 负责代码实验，Scratch 负责图形化实验，课堂功能负责把课程分发给学生。

| 入口 | 用途 |
| --- | --- |
| 总控制台 | 查看运行状态、启动 Jupyter、进入实验 |
| Python 实验 | 打开 Jupyter Lab，运行 Notebook 或 Python |
| Scratch 编程 | 打开内置 Scratch，运行和保存 `.sb3` 项目 |
| 课程资源 | 导入、查看、更新、下载和发布课程 |
| 设置 | 配置 Python、AI、Python 包和课堂 |
| 教师登录 | 解锁教师模式；教师模式才显示课程管理和课堂控制 |

Scratch 是当前维护的图形化编程入口；旧 Blockly 实验只显示“不支持”提示，不要按旧 Blockly 流程操作。

## 2. 安装前准备

### 2.1 电脑要求

- Windows 10/11 x64，或 macOS Apple Silicon。
- Python 3.8 及以上版本。
- 建议准备 8 GB 以上内存和 5 GB 以上可用磁盘。
- 首次导入课程、同步课程和安装依赖时需要联网。

当前正式包不包含 Python 环境；Linux 和 Intel 芯片 macOS 暂无正式安装包。

## 3. 安装与首次启动

### 3.1 Windows

安装包由培训组织者发放：`XEdu Client-2.0.0.exe`。

1. 双击 `XEdu Client-2.0.0.exe`。
2. 按安装向导完成安装。
3. 从开始菜单或桌面打开 XEdu Client。

### 3.2 macOS Apple Silicon

安装包由培训组织者发放：`XEdu Client-2.0.0-arm64-mac.zip`。

1. 解压 `XEdu Client-2.0.0-arm64-mac.zip`。
2. 双击 `XEdu Client.app`。
3. 按系统提示完成首次打开。

不要把源码目录当作安装包，也不要把 Python 环境复制到应用安装目录。

### 3.3 配置本机 Python

打开 `设置 → Python`，按顺序完成：

1. 点击“选择”，选择本机 Python 可执行文件。
2. 点击“确认”。
3. 点击“测试”，确认环境检测通过。
4. 点击“保存设置”。

路径选择：Windows 选择虚拟环境中的 `Scripts\\python.exe`；macOS 选择虚拟环境中的 `bin/python3` 或 `bin/python`。

如果测试提示 `xedu-python` 兼容性问题，点击“修复”后重新测试；版本至少需要 `xedu-python>=2.0.0`。

### 3.4 设置教师口令

首次使用时按页面提示设置至少 4 位的教师口令。应用会在本机安全保存登录凭据，后续启动自动进入教师模式；主动退出教师模式、修改口令或凭据失效后，需要重新输入口令。

完成后检查：

- 总控制台能打开。
- `Python 实验` 中能启动 Jupyter Lab。
- `Scratch 编程` 中能打开内置 Scratch。
- 点击“教师登录”后能看到 `课程资源` 和 `设置`。

## 4. 配置常用设置

### 4.1 Jupyter

在 `总控制台` 点击“启动 Jupyter Lab”；启动成功后可从 `Python 实验` 打开 Notebook。

如果 Notebook 运行失败，先回到 `设置 → Python` 测试环境，再检查课程依赖。

### 4.2 Python 包

打开 `设置 → 包管理`，输入包名后点击“安装”；课程明确要求版本时填写完整版本，例如 `xedu-python==2.0.0`。

默认使用清华镜像，安装失败时先检查网络和 Python 路径。

### 4.3 AI 配置

如需使用 AI 助手，打开 `设置 → AI 配置`，填写 API 类型、API Key、Base URL 和模型后保存；不使用 AI 时可跳过。

## 5. 导入第一门课程

### 5.1 本地导入课程包

这是培训和第一次上课的推荐方式。

本次课程包：[human-pose-control-hardware-0.6.0.zip](http://8.145.44.54:3000/admin/human-pose-control-hardware/raw/branch/main/courses/human-pose-control-hardware/package/human-pose-control-hardware-0.6.0.zip)。

1. 进入 `课程资源`，点击“导入课程 → 本地导入”。
2. 拖入完整的 `.zip` 课程包，或点击选择文件。
3. 等待校验完成，点击“导入到本地”。
4. 返回课程列表，点击课程名称查看详情。

课程包必须包含有效的 `course.json`；不要先手动解压后只选择其中一个文件夹。

### 5.2 从 Gitea 导入课程

本次参考课程：[人体姿态控制行空板 K10](http://8.145.44.54:3000/admin/human-pose-control-hardware)；课程配置：[course.json](http://8.145.44.54:3000/admin/human-pose-control-hardware/raw/branch/main/courses/human-pose-control-hardware/course.json)。

1. 进入 `课程资源`，点击“导入课程 → 云端导入”。
2. 输入完整课程仓库地址：`http://8.145.44.54:3000/admin/human-pose-control-hardware`。
3. 点击“读取课程”，选择课程后点击“导入到本地”。
4. 返回课程列表确认课程已出现。

私有仓库需要在提示框中输入访问令牌；只有读取权限时可以导入，但不能发布更新。

### 5.3 参考课程结构

本次参考课包含两课四个实验：

- 第 1 课：HTML 关键点数据实验、Scratch 实时关键点实验。
- 第 2 课：Notebook 姿态控制实验、HTML 迁移与诊断评测。

硬件实验还需要摄像头、行空板 K10 和串口环境；没有硬件时先完成 HTML、Scratch 和 Notebook 的软件链路。

## 6. 跑通一门课

### 6.1 HTML 实验

1. 打开课程详情，进入 HTML 实验。
2. 按页面提示操作控件或摄像头。
3. 确认页面有结果，再阅读页面中的任务说明。

### 6.2 Scratch 实验

1. 打开课程中的 Scratch 实验。
2. 打开配套 `.sb3` 项目。
3. 点击绿旗运行一次。
4. 修改一个积木参数，再运行一次。
5. 点击保存，并重新打开确认项目仍在。

使用摄像头的实验需要允许摄像头访问，并等待人体感知准备完成。

### 6.3 Notebook 实验

1. 先在 `总控制台` 启动 Jupyter Lab。
2. 从课程详情打开 Notebook。
3. 从上到下运行一个代码单元。
4. 确认出现图片、表格或文字结果。
5. 保存 Notebook。

K10 实验需要先上传或运行课程提供的串口程序，再连接硬件；硬件未连接时不要把“无法运行”判断为软件故障。

完成标准：至少成功运行一个 Scratch 实验和一个 Notebook 或 HTML 实验，并保存一次结果。

## 7. 开一节课

### 7.1 课前设置

打开 `设置 → 课堂设置`，填写课堂名称和教师口令，并勾选：

- 自动发现课堂。
- 允许学生连接本机课堂。

点击“保存设置”。教师机和学生机需要处于可互相访问的同一局域网。

### 7.2 教师开启课堂

1. 在 `课程资源` 打开要上的课程。
2. 选择要上的课节。
3. 点击“开启课堂”。
4. 确认页面显示课堂已开启和课堂码。
5. 先让一台学生机加入，成功后再让全班加入。

### 7.3 学生加入课堂

学生端打开 `课程任务中心`，等待自动发现课堂并点击课堂卡片。

自动发现失败时，在学生端使用教师机地址：

```text
http://<教师机IPv4>:5123
```

例如：`http://192.168.1.23:5123`。

不要填写 `127.0.0.1` 或 `localhost`；如果仍无法连接，检查同网段、防火墙和无线客户端隔离。

### 7.4 结束课堂

课程结束后回到课程详情，点击“结束课堂”；不要直接关机或强制退出应用。

## 8. 管理课程

课程详情页的“更多”菜单可执行：

- 下载课程包：保存当前课程的 ZIP 备份。
- 更新课程：从远端仓库拉取新版本。
- 查看仓库：打开课程对应的 Gitea 页面。
- 删除课程：只删除本机课程记录，操作前先备份。

更新课程前先确认远端版本；应用会在覆盖前保留 `.xedu_backup` 备份。

## 9. 用 skill 创建一节课

### 9.1 安装 skills

每个 skill 均提供独立安装包，首次培训建议全部安装：

- `xedu-course-builder-2026-07-21.zip`
- `xedu-html-lab-2026-07-21.zip`
- `xedu-scratch-lab-2026-07-21.zip`
- `xedu-jupyter-lab-2026-07-21.zip`
- `xedu-pack-2026-07-21.zip`

1. 下载需要的 ZIP，首次培训下载全部 5 个。
2. 分别解压每个 ZIP。
3. 将解压得到的完整 skill 文件夹复制到 Codex skill 目录。
4. 重新打开 Codex，或开始新的对话。

目录：macOS 为 `~/.codex/skills/`；Windows 为 `%USERPROFILE%\\.codex\\skills\\`。

不要只复制 `SKILL.md`；如果已有同名 skill，先备份再覆盖。

### 9.2 每个 skill 做什么

- `xedu-course-builder`：设计课程结构、课节和学习目标。
- `xedu-html-lab`：创建 HTML 互动实验。
- `xedu-scratch-lab`：创建或修改 Scratch 实验。
- `xedu-jupyter-lab`：创建或修改 Notebook 实验。
- `xedu-pack`：检查、打包和发布课程。

### 9.3 创建一节最小课程

在 Codex 中按下面顺序请求：

1. “用 `xedu-course-builder` 设计一节面向七年级的信息科技课，写清学习目标和实验步骤。”
2. “用 `xedu-scratch-lab` 创建一个与目标对应的最小 Scratch 实验。”
3. “用 `xedu-pack` 检查这门课的结构、资源路径和 Scratch 项目。”
4. 在 XEdu Client 导入生成的课程包，按第 6 节跑通。

课程创建原则：先确定教学目标，再选择 HTML、Scratch 或 Notebook；不要为了“凑齐工具”强行添加实验形式。

## 10. 打包与同步到 Gitea

### 10.1 本地打包前检查

使用 `xedu-pack` 检查：

1. `course.json` 能正常读取。
2. 每个实验引用的文件都存在。
3. `.sb3` 项目可以打开和保存。
4. Notebook、HTML 和素材路径没有写错。
5. 至少有一个可运行实验。

检查通过后生成课程 ZIP，再导入 XEdu Client 做一次实际验证。

### 10.2 发布到 Gitea

1. 准备课程仓库地址、分支和写入令牌。
2. 在课程导入/发布流程中选择发布到 Gitea。
3. 确认仓库、课程名称和版本号。
4. 输入有写权限的访问令牌。
5. 点击发布并创建 PR，确认页面返回仓库或 PR 地址。

课程仓库至少要有 `course.json` 和课程资源；对外提供仓库页、`course.json` 地址和课程 ZIP 地址。

参考课程的仓库入口见第 5.2 节，课程包入口见第 5.1 节。

skill 建议单独放在 `xedu-teacher-skills` 仓库，仓库中保留 `README.md`、`INSTALL.md` 和完整的 `skills/` 目录。

## 11. 备份、升级与日志

### 11.1 备份

升级或批量发布前备份：

- 本地课程目录。
- 用户数据目录下的 `config` 目录。
- 已验证可用的课程 ZIP 包。

课程更新前的自动备份通常在课程目录旁的 `.xedu_backup` 中。

### 11.2 升级

当前没有自动更新入口：备份课程和配置，关闭应用，安装新包，再打开验证 Python、课程和 Scratch。

### 11.3 日志

后端日志文件：`backend-process.log`。

- Windows：`%APPDATA%\\XeduClient\\logs\\backend-process.log`
- macOS：`~/Library/Application Support/XeduClient/logs/backend-process.log`

反馈问题时同时提供应用版本、操作系统、课程名称、发生时间、截图和日志文件。

## 12. 常见故障

### Python 检测失败

确认选择的是 `python.exe` 或 `python3`，版本至少为 3.8；重新点击“测试”，必要时点击“修复”。“修复”不要求环境预先安装 Flask，会先独立处理 XEdu/Jupyter；后端启动时再自动准备 Flask 等服务依赖。

### Jupyter 打不开

先测试 Python，再确认 Jupyter 和课程依赖安装在同一个 Python 环境中。

### Scratch 页面打不开

确认使用正式安装包而不是源码目录；退出应用后重新打开，仍失败则重新安装正式包。

### ZIP 导入失败

确认文件是完整 ZIP、内部包含 `course.json`，且没有损坏或重复解压后的多层目录。

### 云端导入失败

检查仓库地址、网络和访问令牌；私有仓库需要读取权限。

### 学生找不到课堂

确认教师已开启课堂、两台电脑在同一可互访网络，再使用 `http://教师机IPv4:5123` 手动连接。

### 课程更新超时

等待页面显示任务完成或失败，不要连续点击；明确失败后检查地址和令牌，再重新发起更新。

### 旧 Blockly 课程显示不支持

这是预期行为；使用课程中的 Scratch 版本，或联系课程维护者补充 Scratch 实验。
