# Course Design Reference

Read this when designing or revising a course rather than performing a narrow file operation.

## Choose An Honest Mode

| Mode | Use when | Required evidence |
| --- | --- | --- |
| `learning-sequence` | Learners need concepts, worked examples, guided practice, or transfer. | Observable outcomes, progression, practice, feedback, and assessment. |
| `project-task` | Learners solve a bounded problem and make or test a product, but full PBL conditions are absent. | Problem, user or scenario, constraints, meaningful choices, test criteria, and revision. |
| `PBL-unit` | The project carries central learning goals through sustained inquiry and public use. | Challenging question, authenticity, inquiry trail, student voice, critique and revision, reflection, public product, and curriculum traceability. |

If a PBL condition is missing, name it and use `project-task` or `learning-sequence`. A polished artifact, multiple digital tools, or a final presentation to the teacher does not establish PBL.

## Design Order

1. Record supplied facts, design choices, and unresolved assumptions separately.
2. Define transfer goals and observable knowledge or performance outcomes.
3. For every outcome, define acceptable evidence and success criteria.
4. Sequence prerequisite knowledge, modeling, guided practice, independent work, transfer, retrieval, and reflection.
5. Add formative decision points: evidence to collect, interpretation, feedback, and the teaching response.
6. Select resources only after the learning and evidence map is complete.
7. Audit time, transitions, cognitive load, accessibility, equipment, network, privacy, safety, and fallback paths.

## Resource Decisions

- Use HTML for focused interactive observation with parameter-linked, copyable code.
- Use Scratch for visible event-driven logic, sprites, stage feedback, camera sensing, and block programming.
- Use Jupyter for executable Python, data, charts, model results, and inspectable reasoning.
- Combine forms only when each has a distinct learning role and shared terms, parameters, and assets stay consistent.
- Preserve useful existing materials, but remove or defer resources that do not support an outcome or evidence need.

## Quality Gates

- An artifact is evidence only when it reveals the intended reasoning or performance.
- Assessment is formative only when evidence changes the next teaching or learning action.
- A group product does not prove each learner's understanding; include individual evidence.
- Integration claims require an observable data or control path.
- Impact claims require evidence beyond feasibility or a brief demonstration.
- Runtime, model, camera, hardware, and network limitations must remain explicit.
