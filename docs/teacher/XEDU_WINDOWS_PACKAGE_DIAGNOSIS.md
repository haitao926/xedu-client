# Windows 2.1.4 课程包启动失败排查

现场信息：客户端 2.1.4，平台地址 `10.74.136.127`，提示“课程包校验失败，请从学习平台重新打开”。实际访问协议和端口尚未确认。

## 已确认的失败链路

2.1.4 将下载大小、SHA-256、ZIP 解压、课程清单和资源缺失分别返回不同的错误。平台授权接口仍可返回 `package_invalid`，客户端会把平台原始信息覆盖为上面的笼统提示。

已用以下平台响应复现同样提示：

```json
{
  "ok": false,
  "code": "package_invalid",
  "message": "课程包配置不完整，请让老师重新上传课程包后再打开。"
}
```

HTTP 状态为 400，唯一请求是 `/api/xedu/v1/launch/exchange`；没有下载 ZIP，也没有调用本地课程目录查找。授权失败不能靠删除客户端缓存或覆盖课程目录解决。

平台 `XEduApiHandler.Exchange` 的这条错误覆盖五项检查：课程版本、下载地址、下载地址与平台是否同源、SHA-256 格式、字节大小。尚未读取现场服务器数据库，不能断言其中哪项失效。

## 服务器检查

在 `10.74.136.127` 的 SQL Server 中选择学习平台实际使用的数据库，运行 [只读检查脚本](diagnose_xedu_platform_package.sql)。脚本只执行 SELECT；不读取授权令牌、学生账号或密码，不更新数据。

脚本开头默认 `http://10.74.136.127`。如浏览器实际使用 HTTPS 或其他端口，先将 `@PlatformOrigin` 改成实际的协议、主机和端口。

依次查看课程包绑定、活动绑定和最近启动记录。启动记录是授权创建时的快照，不能只核对 `XEduCoursePackage`，忽略活动或启动记录的旧字段。

平台上传代码会保存上传当时的绝对下载地址。数据库迁移或服务器 IP、协议、端口改变后，旧地址可能不再同源。脚本中的 URL 比较用于定位疑点；localhost 地址还需要核对现场运行代码是否执行了地址改写。

修复需针对检查结果：补齐缺失元数据；对地址不一致的本平台课程包重新绑定到实际访问地址；大小或 SHA-256 必须从服务器实际 ZIP 计算。不要仅为了通过检查把校验值随意修改。修复绑定后从平台新建启动链接，避免继续使用旧启动快照。

## 验证边界

本机 macOS 的平台容器与学校服务器不是同一部署。本机默认绑定地址为 `https://localhost:8443`，不能据此判断学校数据库内容。当前环境直连 `10.74.136.127` 的 HTTP 返回空响应，HTTPS 连接超时，尚未获得学校平台的实际授权响应或数据库结果。Windows 实机成功打开仍待确认。
