# XEdu Client 课程文件夹契约（v1）

`xedu-client` 在 v1 中只负责接收、校验、预览、运行和发布课程。
外部 AI 或其他工具如果要与它衔接，主交付物应当是一个本地课程文件夹，或 `xedu-pack` 生成的标准课程包。

## 1. 什么是课程根目录 / 课程包

- 老师在“课程资源”里选择的是整门课程的根目录。
- 根目录建议直接包含 `course.json`。
- 如果目录里还没有 `course.json`，应先由外部打包工具或课程创作工具完成初始化，再交给 `xedu-client` 导入。
- 如果走“课程导入”，建议直接提供 `xedu-pack` 生成的 zip 包或已解压目录，而不是任意本地文件夹。

## 2. `course.json` 最低要求

最少需要满足：

```json
{
  "id": "course-id",
  "title": "课程名称",
  "sections": []
}
```

说明：

- `id` 为空时，系统可按课程标题补生成。
- `title` 必填。
- `sections` 必须是数组；为空时可以后续在资源页中继续补课节和实验。

## 3. 实验材料文件夹

- 一个实验对应一个材料文件夹。
- 材料文件夹必须位于课程根目录内。
- 常见支持文件包括：
  - `.ipynb`
  - `.py`
  - `.html`
  - `.sb3`
  - 旧 `.blockly.xml` / `.blockly.json`（仅用于识别并显示不支持提示，不可写入或运行）
  - 图片资源
  - 数据文件

`xedu-client` 会把这些文件识别为实验资源，用于预览、运行或继续整理。

## 4. QuickForm 注入边界

- QuickForm 在 `xedu-client` 中的定位是“对已有 HTML 实验做注入”。
- 注入目标必须是课程目录内的 `.html` 或 `.htm` 文件。
- 注入前应先确认实验已经关联正确的 HTML 文件和 QuickForm 提交地址。

## 5. 发布前最低检查

在资源页发布当前课程目录前，至少确认：

- 课程根目录可正常读取
- `course.json` 可解析
- 至少存在 `1` 个实验
- 实验材料路径位于课程目录内
- 需要注入 QuickForm 的实验已绑定到正确 HTML 文件

## 6. v1 不做什么

以下内容不作为 `xedu-client` 的内置能力：

- 外部 skill 编排
- 自动生成 Blockly 草稿；Blockly 编辑器已移除，旧格式不再作为新课交付物
- 自动课程打包智能流程
- 自动 QuickForm 工作流接入

这些能力如果存在，应由外部工具先产出课程文件夹，再交给 `xedu-client` 处理。

补充：

- “导入课程”只面向两类输入：
  - `xedu-pack` 生成的标准课程包
  - 云端课程仓库中的课程资源
