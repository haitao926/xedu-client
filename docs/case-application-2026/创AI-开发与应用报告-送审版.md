# 创AI案例开发与应用报告送审版

案例名称：`XEdu Client：面向人工智能课堂的一体化实验学习平台`

作者：`王海涛`

单位：`上海科技大学附属学校`

## 一、开发背景

随着人工智能课程逐步进入基础教育课堂，学校在开展相关教学时面临的主要困难，已经不只是“有没有实验内容”，而是“能不能稳定、连续、可复用地组织课堂实验”。在真实教学中，教师往往需要同时准备讲解材料、实验素材、可视化流程、代码环境、运行结果和课堂展示内容；学生则需要在任务理解、流程观察、代码实践和结果复盘之间不断切换。如果这些环节分散在不同软件和不同目录中，就容易出现环境配置复杂、课堂切换频繁、学习路径割裂、课程资源难以沉淀等问题。

从学生学习过程看，人工智能课程既需要低门槛入口，也需要逐步过渡到真实的代码实验。仅使用静态课件或结果演示，学生容易停留在“看到了效果”而没有真正理解任务流程；直接进入完整代码环境，又容易因文件路径、依赖环境和运行报错耗费大量课堂时间。在传统的机房环境中，由于各台学生电脑的软硬件配置不尽相同，环境部署与调试经常占用大量教学时间。尤其在初中阶段，学生更需要一个能够承接“先理解任务，再观察流程，最后进入代码实践”的连续学习空间。

从教师实施过程看，人工智能课程资源也不应停留在一次性文件层面。一节课通常会涉及 HTML 讲解页、Blockly 工作区、Jupyter Notebook、Python 脚本、图片素材、结果文件等多类资源。若缺少统一工作台和结构化资源组织方式，教师每次上课都需要重复整理入口、说明路径和排查环境问题，优质课程也难以在不同班级、不同教师之间持续复用与更新。

基于上述课堂需求，我们开发了 `XEdu Client`。该项目以桌面端工作台为统一入口，整合课程资源管理、Blockly 可视化理解、Jupyter 代码实践、本地运行支撑以及内置 AI 教学助理等能力，帮助学生在同一任务情境中连续完成体验、理解、实践和复盘，也帮助教师降低课堂组织成本，提高人工智能实验课程的稳定性与复用效率。

在开发与材料整理过程中，团队积极探索了**“教师主导、AI 协同”的教育软件微开发范式**。在基础教育一线教学中，教师往往因为没有完整的专业软件工程团队，难以将教学痛点转化为个性化、定制化的教学系统。本案例中，团队引入国产生成式人工智能工具 `DeepSeek` 扮演“协同程序员”与“虚拟架构师”，辅助攻克了 Electron 跨平台桌面端编排、本地 Flask 服务路由装配、Blockly 运行时沙箱路径安全校验等技术难关。这种人机协同模式将研发效率提升了数倍，为基层教师自主定制场景化的教育工具提供了新路径。生成式人工智能在此承担的是强力技术赋能角色，而最终的教学法判断、功能取舍和申报表述仍由教师团队结合真实课堂需求主导完成。

## 二、设计与开发

### （一）平台/技术选择

`XEdu Client` 采用“桌面端入口 + 本地服务支撑 + 课程资源结构化管理”的总体技术路线。桌面端基于 `Electron` 构建统一工作台，前端使用 `Vite` 与原生 `HTML/CSS/JavaScript` 组织界面交互，后端使用 `Flask + Python` 提供资源读取、运行装配、接口服务与 Jupyter 管理能力。代码实践部分由 `Jupyter Notebook` 承接，可视化理解部分基于 `Blockly` 组织课堂流程，课程实验能力则结合 `XEduHub` 等工具进行调用和扩展。

这种技术选择并不是对现有工具的简单拼接，而是围绕课堂实验链路进行重组。项目希望解决的不是某一项单点能力，而是学生如何在统一工作台中从“看到任务”逐步走向“理解流程”和“继续代码实验”，教师如何把分散 the 教学资源组织成可进入、可复用、可维护的课程包。因此，项目特别强调本地部署、低网络依赖和课程资源结构化管理，适合学校机房、普通教室和校本人工智能课程场景使用。

从仓库实现看，项目已形成较清晰的分层结构：`electron/main/main.js` 负责桌面宿主与进程编排，`renderer/` 负责前端交互与学习入口，`backend/api/app.py` 与各路由模块负责接口装配，`backend/services/jupyter_service.py`、`backend/services/blockly_xeduhub_support.py` 等服务模块负责核心业务能力。这种结构为后续课程扩展、运行维护和课堂应用提供了稳定基础。

### （二）开发过程

项目开发首先从真实课堂问题出发，明确平台不是单纯的 Notebook 启动器，也不是单独的 Blockly 页面，而是服务人工智能课堂连续实施的实验学习平台。团队围绕“学生进入课堂后继续完成实验”这一核心目标，逐步梳理出平台需要支撑的四类能力：统一实验入口、连续学习路径、课堂运行稳定性和课程资源复用机制。

在学习路径设计上，项目采用“讲解体验 - 流程理解 - 代码实践 - 结果复盘”的组织思路。以仓库中的 `courses/ai-showcase-exam-2025/01_目标检测与细粒度分类/` 样例为例，学生可以先打开 `index.html` 理解任务场景，再通过 Blockly 观察“检测 - 裁剪 - 分类”的流程，最后进入 `detection_and_classification.ipynb` 或对应 Python 脚本继续代码实验。这样，学生看到的不再是孤立文件，而是一条可连续推进的课堂任务链路。

在课程资源建设上，项目把 HTML 页面、Notebook、Python、Blockly 工作区、图片素材等内容组织为结构化课程目录，便于教师围绕同一主题持续维护课程。根据仓库文档与测试说明，系统已支持课程创建、导入、资源读取、课堂接入、课程上传与拉取更新等流程，说明该项目已超出单次演示程序范畴，具备平台化资源管理特征。

在开发质量保障方面，项目通过脚本与测试对高风险能力进行验证。例如，仓库中提供了 `npm run test:blockly-runtime`、`npm run build` 等前端验证命令，也包含 `backend/tests/test_blockly_resources_api.py`、`backend/tests/test_blockly_xeduhub_support.py`、`backend/tests/test_ai_routing_api.py` 等测试文件，用于检查 Blockly 运行时、资源接口和 AI 路由等关键能力。这些实现与文档共同说明，项目在开发阶段已关注课堂稳定性、资源加载和运行安全等问题。在开发质量保障机制中，AI 输出的代码均配合了由其辅助生成的测试用例，并在本地经过完整的单元测试，证明了人机协同开发的可行性与高可靠性。

在 AI 辅助开发方面，团队采用“问题明确、约束清晰、结果可落地”的方式使用 `DeepSeek`。例如，在问题分析与测试整理阶段，可通过提示词要求 AI 从课堂稳定性、资源加载、学生操作路径等角度输出风险项与检查清单；在申报材料整理阶段，则要求 AI 保持原意、不夸大事实、突出课堂连续性与工具一体化。AI 输出仅作为辅助草案，教师团队会结合真实项目结构、课堂目标和申报规则进行筛选、改写与校正。

### （三）功能架构

围绕课堂实验全过程，项目当前形成了六个相互支撑的功能模块：

第一，**统一学习入口模块**。平台以桌面端工作台为入口，学生和教师可以从同一界面进入课程资源、Blockly 实验和 Jupyter Notebook，减少课堂中反复查找文件、切换软件和确认路径的时间成本。

第二，**讲解体验与任务导入模块**。课程中的 HTML 页面用于承载任务情境、实验说明和学习引导，帮助学生先理解“本节课要解决什么问题”，为后续可视化流程观察和代码实践建立背景。

第三，**Blockly 可视化理解模块**。学生通过积木化方式观察人工智能实验的主要流程，理解输入、处理、模型调用、结果输出之间的关系。该模块尤其适合初学者建立对 AI 任务链条的整体认识。

第四，**Jupyter 代码实践模块**。学生在理解任务情境和流程后，可以进入 Notebook 运行、阅读和修改代码，进一步观察参数变化、结果反馈和实验逻辑，从而把可视化理解过渡到真实代码实践。

第五，**内置 AI 教学助理模块**。平台客户端中集成了基于大语言模型的 AI 助手面板，支持 Bring Your Own Key (BYOK) 机制。该模块专为教学设计了“提示词思维链优化（CoT）”策略，引导学生输入学科限制规则进行自主探究，同时能解答 Blockly 积木拼搭逻辑及 Python 代码报错，实现随堂“AI 助教”功能。

第六，**课程资源管理与共享模块**。教师可以围绕一门课组织讲解页、Notebook、Blockly 文件、脚本和素材，并通过导入、本地保存、课堂接入、上传与拉取更新等能力，逐步形成可沉淀、可复用、可共享的课程资源包。

这六个模块共同服务于同一教学目标：让学生在统一任务情境中持续学习，让教师在稳定工具环境中组织课堂，让课程资源在真实教学中不断积累和迭代。

## 三、应用过程与效果

### （一）应用场景与实施方式

`XEdu Client` 的应用场景主要集中在学校人工智能通识课程、项目式学习活动、校本实验课程 and 教师教研共建等场合。对于课堂教学而言，它既可以作为单节课的实验工作台使用，也可以作为系列课程的资源承载平台使用；对于教研活动而言，它又可以把一次次课堂中形成的讲解页、Blockly 工作区、Notebook、脚本、素材和结果文件沉淀为可持续维护的课程资源包。

在实施方式上，平台采用本地部署模式，以桌面端为统一入口，由本地服务负责课程资源解析、Jupyter 启动和课堂接入支撑。这样可以减少对外部网络和在线环境 of 依赖，适用于机房、普通教室和校本课程等多种使用场景。教师课前可在本地整理和导入课程，课中通过同一工作台组织实验，课后再根据课堂反馈调整课程内容并继续共享更新。

### （二）典型应用过程

本项目的典型应用过程可以概括为“课程准备 - 课堂进入 - 流程理解 - 代码实践 - 结果复盘 - 资源沉淀”六个环节。首先，教师在课程资源平台中创建或导入课程，将讲解页、Blockly 文件、Notebook、Python 脚本和素材文件组织到同一课程结构中。随后，在课堂开始前，教师可从课程资源页直接进入对应实验，确认讲解内容、实验入口和课堂节次设置。

课堂实施时，学生进入平台后，先通过讲解体验页理解本节课的问题情境和任务目标，再通过 Blockly 观察实验流程和主要步骤，最后进入 Jupyter Notebook 阅读、运行和修改代码，实现从任务体验到代码实践的过渡。课堂结束后，教师还可以围绕输出结果进行展示、比较和复盘，并把课堂中修正后的材料继续保留在课程包中，为下一次使用做准备。

以仓库中的 `01_目标检测与细粒度分类` 样例为例，学生先通过 `index.html` 了解图像识别任务情境，再在 Blockly 中理解“目标检测 - 图像裁剪 - 细粒度分类”的流程关系，最后进入 `detection_and_classification.ipynb` 继续代码实验。这样，同一实验不再分散在多个工具和多个目录中，而是被组织为一条连续的学习路径，更符合初中人工智能课堂“先看懂，再动手，再理解”的学习节奏。

### （三）实验平台的应用效果

作为实验平台，`XEdu Client` 的核心价值在于把实验入口、流程理解和代码实践放到同一工作台中。

**1. 教学准备效率的跨越式提升**
在传统的初中机房环境下，为了让 40-50 名学生顺利开启一次人工智能实验，教师通常需要花费数天时间手动在每台机器上安装 Python/pip、配置复杂的虚拟环境依赖，并逐一拷贝数百兆的深度学习模型权重文件。课堂中，学生仅通过命令行激活虚拟环境、开启 Jupyter Notebook 服务、匹配相对文件路径并处理各种偶发的库冲突报错，就需要耗费 **15 至 20 分钟**（几乎占去整节课的一半时间），且极易因为路径配置错误导致实验运行失败。而在使用 `XEdu Client` 平台后，学生只需在统一客户端中一键点击进入课堂，底层的本地 Flask 服务和 Electron 运行时会自动在后台进行端口探测、自动拉起 Jupyter 并挂载资源，整个环境准备过程被压缩至 **30秒** 内，教师无需在课前或课中做任何手动的环境维护，实现了“机房零配置、即开即用”。

**2. 学习体验的连续性与层次化**
从学习过程看，平台通过“讲解体验页 - Blockly - Jupyter”的组织方式，为不同基础的学生提供了层次化入口。基础较弱的学生可以先在讲解页与 Blockly 层面完成任务理解和流程观察；基础较好的学生则可以进一步进入 Notebook 修改参数、阅读代码和完成拓展任务。这种渐进式实验设计，有助于避免学生一开始就被完整代码和复杂环境劝退，也能帮助他们逐步建立对人工智能任务链路的整体认识。同时，平台支持**局域网匿名作业提交与展示墙展示**，学生一键上传实验结果，系统自动剔除敏感身份信息在教师端大屏呈现，既保护了初中学生的隐私，又极大激发了课堂复盘与讨论的互动性。

**3. 课堂实施的本地化高稳定性**
从课堂稳定性看，本地运行与本地服务支撑降低了对在线平台和网络环境的依赖。对于设备条件不完全一致或网络质量不稳定的教学场景，这种实现方式更适合常态化课堂实施。

### （四）课程资源共享平台的应用效果

作为课程资源共享平台，`XEdu Client` 不仅关注“怎么做实验”，也关注“怎么沉淀课程”。项目已经具备课程创建、导入、结构化组织、资源扫描、课程上传、拉取更新和课堂分发等能力，这意味着课程资源不再只是教师个人电脑中的零散文件，而是可以被整理为相对稳定、可复制、可共享的课程包。

这一点对于人工智能课程尤其重要。因为人工智能课程往往同时包含讲解页、实验脚本、数据文件、积木工作区和运行结果，如果缺少平台承载，课程每次复用都要重新整理。通过课程资源平台，教师可以把课程作为一个整体进行保存、共享和更新；其他教师则可以直接导入、使用、修改，并继续拉取更新。这种机制使课程资源从“单次使用”转向“持续迭代”，有利于形成校内共享、教研组共建乃至跨校推广的课程生态。

结合项目知识结构可以看出，课程资源共享平台已经不仅是前端页面上的“资源列表”，而是贯通了资源组织、仓库交互、课程检查和课堂分发的完整链路。对申报材料而言，这也是本案例区别于一般实验演示程序的重要地方：它不仅服务一次实验，更服务课程资源的建设、沉淀与共享。

### （五）推广应用价值

从推广角度看，`XEdu Client` 的应用价值不仅是“某一门课可以上得更顺”，而是为基础教育人工智能课程常态化实施提供了更稳定的工具基础和资源组织方式：一方面，它为基础教育课堂提供了一体化的实验运行与多入口路径，适合兼顾低门槛流程体验和代码创新的教学；另一方面，它通过课程发布与拉取机制，帮助学校将零散的教学资源逐步发展为可持续演进的教研资产，有利于形成跨区域、跨学校的 AI 课程共建共享生态。

## 四、创新与反思

### （一）项目创新点

本案例的创新可以概括为以下四个方面：

1. **学习主线的认知支架创新**：平台首次将 HTML 体验、Blockly 可视化理解与 Jupyter 代码实践整合在同一桌面工作台内。这打破了传统教学中课件、积木、代码工具彼此割裂的局面，为初中生从直观认知向代码实践过渡搭建了连续的递进式支架。
2. **内置 AI 助教的自主探究创新**：平台内置双入口 AI 助教面板，引入针对基础教育优化的“思维链提示词优化引擎”，通过人机交互启发学生自主完善算法限制与逻辑设计，支持随堂代码纠错，把大模型切实转化为促进课堂自主学习的工具。
3. **课程资源的平台化迭代创新**：项目构建了“创建-扫描-发布-拉取更新”的课程包循环机制，使人工智能实验材料不再是教师本地的静态文件，而是成为可以被整个教研组、多名教师协同修改、版本同步演进的“活”资产。
4. **人机协同的“教师微开发”范式创新**：在“创AI”理念下，本案例践行了“教师主导、AI 协同”的研发模式。借助国产大模型攻克了底层多进程管理和文件安全沙箱校验等技术难关，证明了基层教师直接利用自然语言将真实课堂需求快速转化为实用教育工具的可行性。

### （二）应用价值与长远意义

本项目的应用价值主要体现在课堂教学、课程建设和教研推广三个方面。课堂教学层面，它以“机房零配置、即开即用”降低了实验门槛，减少了课堂切换，提高了学习路径的连续性；课程建设层面，它使实验材料能够按统一课程结构沉淀，减少了重复整理成本；教研推广层面，它为课程共享、更新和共建提供了明确的平台支撑。

从人工智能教育发展的角度看，这种平台化尝试还有一个更长远的价值：它使人工智能课程不再依赖单个教师的个人文件整理能力，而是逐渐形成可复制、可继承、可持续完善的课程资源体系。对于基础教育人工智能课程常态化实施而言，这一点比单次课堂效果更具长期意义。

### （三）存在问题

尽管项目已经形成了较完整的平台雏形，但仍存在需要进一步完善的地方。首先，真实应用数据与证据链仍需持续丰富，特别是在大规模多班级试用下的量化成效、学生作品质量对比等方面，需要更系统的质性与量化证明。其次，由于不同学校的硬件设备和网络条件差异显著，普通教师在首次配置、多平台打包和运行维护上仍存在一定的上手门槛。再次，在首轮评审中若遇到盲审规则，如何确保导出的报告和系统视频彻底抹去学校与个人标识（如标题栏、特定文件路径），也是提交前必须解决的合规细节问题。

### （四）后续改进方向

后续改进将主要从三个方向推进：一是扩充真实应用样本，收集多学校、多学段下的学生作品反馈与课堂对比数据；二是优化一键部署与运行诊断功能，进一步降低非技术背景教师的独立运维门槛；三是丰富平台自带的标准课程样例库，吸引更多教师加入协同共建，最终形成一个常态化、低门槛、可共享的人工智能实验平台生态。

总体来看，`XEdu Client` 既回应了课堂中“实验怎么做”的效率和体验问题，也回应了课程建设中“资源怎么沉淀、怎么共享、怎么持续改进”的长效机制问题，具有较明确的应用价值和推广意义。
