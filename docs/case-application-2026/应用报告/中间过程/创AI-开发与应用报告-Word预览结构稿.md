# 创AI案例开发与应用报告

案例名称：`XEdu Client：面向人工智能课堂的一体化实验与课程资源共享平台`

作者：`王海涛`

单位：`上海科技大学附属学校`

## 一、开发背景

随着人工智能教育逐步进入基础教育课堂，学校在开展人工智能课程时面临的不只是“有没有一节课”的问题，更是“能不能稳定、连续、可复用地开展课堂实验”的问题。实际教学中，教师常常需要同时处理讲解材料、可视化操作、代码环境、实验素材、运行结果和课堂组织等多个环节。若这些环节分散在不同工具中，学生就容易在频繁切换中丢失任务上下文，教师也需要花费较多时间处理环境配置、文件查找、软件切换和运行排错，课堂时间难以集中用于理解、探究和表达。

基础教育阶段学生的认知基础差异较大，小学、初中、高中对人工智能实验的学习入口也并不相同。小学阶段更需要从情境体验和积木化操作进入，初中阶段需要在任务理解和流程建构之间建立联系，高中阶段则需要进一步进入代码实践、实验探究和结果分析。如果课堂工具只面向单一学段或单一操作方式，就很难支撑人工智能课程由浅入深、持续推进。

人工智能课程资源建设也存在分散化问题。讲解页、Notebook、Blockly 工作区、Python 脚本、图片素材、实验输出和说明文档如果缺少统一组织方式，往往只能服务一次课堂，难以沉淀为可复用、可共享、可推广的课程包。许多优质课程材料在第一次课堂实施后没有被结构化保存，后续教师再次使用时仍然需要重新寻找文件、重建路径、确认运行环境，导致课程建设投入难以持续发挥价值。

基于上述问题，我们开发了 `XEdu Client`。平台面向基础教育人工智能课堂，围绕“从体验到理解、从实践到应用”的课堂实验链路，整合讲解体验页面、基于 `XEdu Pro` 封装的 Blockly 可视化实验、Jupyter 代码实验、实验结果查看、课堂接入、课程资源管理与共享等功能，帮助学生在统一任务情境中连续完成体验、理解、实践、验证和复盘，也帮助教师降低课堂组织成本，提高课程资源复用效率和课堂实施稳定性。

本案例的核心不是单一课件，也不是某一个代码运行工具，而是围绕人工智能课堂真实需求建设的实验与课程资源共享平台。平台采用的是一套“组合拳”：`XEdu Client` 负责统一入口、本地服务、应用装配和课程资源组织；`XEdu Pro` 通过 Blockly 方式封装人工智能实验能力，让复杂模型调用和流程组织变成可操作的积木任务；Jupyter 则承接进一步的代码阅读、运行和修改。三者共同解决人工智能实验课中“进入难、理解难、运行难、复盘难”的问题，也共同解决课程资源“分散、难找、难迁移、难共建”的问题。

在开发过程中，团队还使用国产生成式人工智能工具 `DeepSeek` 辅助开展需求梳理、问题分析、测试清单整理和申报文稿润色。通过人机协同方式，教师能够更快把真实课堂需求转化为可运行、可复用、可说明的教育工具成果，也能在较短时间内完成技术实现、材料整理和应用反思。

## 二、设计与开发

### （一）项目总体定位

`XEdu Client` 的总体定位可以概括为两个方面：一是面向人工智能课堂的实验平台，二是面向课程建设与共享的平台。这两个定位并不冲突，而是同一人工智能课堂应用场景中的前后两端。实验平台关注课堂中学习如何发生，课程资源共享平台关注课堂资源如何沉淀、流转和再次使用。

#### 1. 面向人工智能课堂的实验平台

作为面向人工智能课堂的实验平台，`XEdu Client` 不是简单打开某个网页或某个 Notebook，而是把讲解体验、`XEdu Pro` Blockly 可视化实验、Jupyter 代码实验、实验结果查看和继续学习组织在同一任务链路中。学生进入平台后，可以从同一个课程主题出发，先理解任务背景，再通过积木化流程观察人工智能任务如何运行，最后进入代码环境进行实践和拓展。这样的定位强调“实验连续性”，让学生不再在多个工具之间迷路。

#### 2. 面向课程建设与共享的平台

作为面向课程建设与共享的平台，`XEdu Client` 又不是只服务一次课堂的实验启动器。平台支持把讲解页、Blockly 工作区、Notebook、Python 脚本、图片素材、说明文档和结果文件组织为课程资源包，使课程能够被创建、导入、管理、分发、上传、发布、拉取更新和协同复用。这样的定位强调“资源可持续”，让一次课堂中的实验材料能够变成后续课程建设和教研共建的基础。

因此，本项目的设计不是把学生学习和课程管理割裂成两套系统，而是以课程包为核心，把“课堂实验入口”和“课程资源共享”连接起来。课程包既是课堂实验的入口，也是课程资源共享的单位；既承载学生的学习路径，也承载教师的课程建设成果。

### （二）总体架构设计

项目采用“桌面宿主与应用装配 + 后端运行与服务支撑 + 前端实验工作台 + 课程与实验资源组织结构”的总体架构。桌面端基于 `Electron` 构建，前端使用 `Vite`、`HTML/CSS/JavaScript` 实现统一学习入口和课堂交互界面，后端使用 `Flask + Python` 提供课程资源读取、运行时装配、接口服务和 Jupyter 管理能力。实验实践部分使用 `JupyterLab/Notebook` 支撑代码阅读、运行与修改，可视化理解部分通过 Blockly 封装 `XEdu Pro` 的实验能力，使学生能够用积木方式调用和组织人工智能任务。

#### 1. 桌面宿主与应用装配

桌面宿主与应用装配负责把分散能力组织成统一客户端。`Electron` 提供桌面应用外壳，使平台能够在学校机房、普通教室和本地电脑环境中以统一入口运行。应用装配层负责连接前端页面、本地服务、课程目录和实验入口，使用户面对的是一个完整工作台，而不是若干需要手动拼接的软件窗口。

#### 2. 后端运行与服务支撑

后端运行与服务支撑负责把课程资源和实验环境稳定地接起来。`Flask + Python` 服务用于处理课程资源读取、文件路径解析、接口调用、Jupyter 启动与管理、Blockly 资源关联等任务。对于人工智能课堂来说，后端服务的价值不只是“能运行”，更在于把路径、端口、资源加载和实验入口等容易出错的环节收束到平台内部，降低课堂临时排错压力。

#### 3. 前端实验工作台

前端实验工作台负责承载学生可见的学习路径。工作台中既有课程讲解体验页，也有 `XEdu Pro` Blockly 可视化实验入口，还有 Jupyter Notebook 代码实验入口。前端不是简单的按钮集合，而是围绕“体验 - 理解 - 实践 - 复盘”的学习顺序组织，让学生能够从一个主题持续推进。

#### 4. 课程与实验资源组织结构

课程与实验资源组织结构负责把课堂材料沉淀为课程包。课程包中可以包含 `index.html` 或说明页、`XEdu Pro` Blockly 工作区文件、Notebook、Python 脚本、图片或数据素材、实验输出和说明文档。这种结构让课程资源从“文件堆”变成“可进入、可理解、可迁移”的课程单元，也为后续上传、发布、拉取更新和协同共建提供基础。

整体来看，平台架构形成了清晰分工：`XEdu Client` 提供桌面入口、运行支撑和资源组织，`XEdu Pro` 提供可视化人工智能实验封装，Jupyter 提供代码实践空间，课程资源包则把学习路径和实验材料组织为可复用资产。这正是本案例所强调的组合拳。

### （三）实验平台功能设计

实验平台功能设计是本项目的核心。平台围绕人工智能课堂中学生完成实验的真实路径，形成了统一实验入口、讲解体验页、Blockly 可视化实验、Jupyter 代码实验、实验结果查看与继续学习、课堂接入与实验上下文保留等功能。这些功能共同解决“如何进入实验、如何理解实验、如何实践实验、如何复盘实验、如何继续学习”的问题。

#### 1. 统一实验入口

统一实验入口是实验平台的第一层能力。学生进入 `XEdu Client` 后，可以从课程资源直接进入当前实验，不需要先打开多个软件、查找多个目录或手动输入复杂路径。统一入口把课程页面、Blockly 工作区、Notebook 和实验素材放到同一课程主题下，减少了课堂中反复说明“文件在哪里、入口在哪里、下一步点哪里”的时间消耗。对课堂来说，统一入口的价值是让学习尽快进入任务，而不是停留在工具准备上。

#### 2. 讲解体验页

讲解体验页承担任务导入和学习引导功能。它通常以 HTML 页面形式呈现，包含任务情境、实验目标、操作说明、知识提示和必要的代码或素材说明。学生可以先通过讲解页了解本节课要解决什么问题、为什么这个问题与人工智能有关、实验输入是什么、预期输出是什么。讲解体验页让人工智能实验不再只是技术操作，而是有情境、有问题、有目标的学习活动。

#### 3. Blockly 可视化实验

Blockly 可视化实验是实验平台中的关键功能，也是 `XEdu Pro` 能力进入课堂的重要方式。这里的 Blockly 不是普通的积木拼图，而是对 `XEdu Pro` 人工智能实验能力的可视化封装。通过积木方式，学生可以组织读取图片、调用模型、目标检测、图像裁剪、分类识别、结果展示等流程，把复杂的模型调用和处理过程转化为可观察、可操作的任务链。它特别适合人工智能初学者先建立流程理解，再逐步进入代码实践。

`XEdu Pro + Blockly` 的价值在于降低人工智能实验的入门门槛。许多学生一开始并不能理解完整 Python 代码，也难以直接理解模型推理过程。通过 Blockly，他们可以先看到人工智能任务大致由哪些步骤组成，每一步输入什么、输出什么、怎样连接到下一步。这样，学生在进入 Jupyter 之前已经具备了流程图式的理解，后续阅读代码时就不再是从零开始。

#### 4. Jupyter 代码实验

Jupyter 代码实验承担从可视化理解走向真实代码实践的任务。学生在 Notebook 中可以阅读代码、运行代码、观察输出、修改参数并比较结果。与 Blockly 相比，Jupyter 更适合展开算法逻辑、变量变化、参数调试和实验拓展。平台把 Jupyter 与前面的讲解页、`XEdu Pro` Blockly 工作区放在同一课程包中，使学生能够在同一主题下完成从“看懂流程”到“运行代码”的过渡。

#### 5. 实验结果查看与继续学习

实验结果查看与继续学习功能用于连接课堂讨论和后续拓展。人工智能实验的结果可能包括图片检测框、分类结果、裁剪图、Notebook 输出、运行日志或学生修改后的结果。平台将这些结果纳入同一课程链路，使学生能够围绕结果解释模型表现、比较不同参数、讨论误差原因，并在下一次学习中继续使用已有材料。这一功能让实验不是“运行一次就结束”，而是可以成为复盘、表达和继续探究的证据。

#### 6. 课堂接入与实验上下文保留

课堂接入与实验上下文保留功能用于保障课堂连续性。学生从课程资源进入实验后，平台尽量保留当前课程、当前实验、当前 Blockly 工作区和当前 Notebook 的上下文关系，避免学生在工具切换中丢失任务线索。教师组织课堂时，也可以围绕同一课程包安排讲解、操作、实践和复盘。对人工智能课程来说，上下文保留非常重要，因为一个实验往往同时包含任务、素材、模型、流程、代码和结果，任何环节脱节都会影响学生理解。

这些实验功能共同形成了平台的核心学习路径：统一入口让学生进入任务，讲解体验页建立情境，`XEdu Pro` Blockly 帮助学生理解流程，Jupyter 支撑代码实践，结果查看促进复盘表达，课堂接入与上下文保留保证学习链路不断裂。相比单独使用 Blockly 或单独使用 Notebook，这种组合更适合基础教育人工智能课堂的真实节奏。

### （四）课程资源共享平台功能设计

课程资源共享平台功能设计是本项目的另一条核心主线。人工智能课程不是一次性演示，课程材料也不应只停留在个人电脑中的零散文件。平台围绕课程创建与导入、课程资源组织与管理、课程资源共享、课程上传与发布、课程拉取更新、课程协同共建与复用、课堂课程包分发等环节，形成完整的课程资源闭环。

#### 1. 课程创建与导入

课程创建与导入功能用于建立课程包入口。教师可以围绕一个人工智能主题创建课程，也可以导入已有课程资源。课程创建时需要明确课程名称、课程目录、讲解页、实验文件、素材和相关说明；课程导入时则将已有的讲解页、Notebook、Blockly 工作区、脚本和素材纳入统一课程结构。通过创建与导入，原本散落的教学材料被转化为平台可识别、可进入的课程资源。

#### 2. 课程资源组织与管理

课程资源组织与管理功能用于维护课程内部结构。一个完整课程包通常包括讲解体验页、`XEdu Pro` Blockly 工作区、Jupyter Notebook、Python 脚本、图片或数据素材、实验输出和说明文档。平台将这些资源放在同一课程主题下管理，使教师能够清楚看到一节课的材料组成，也方便后续修改、替换和补充。资源管理的重点不是堆放文件，而是让每个文件都服务于学习路径。

#### 3. 课程资源共享

课程资源共享功能用于推动优质资源流转。教师完成一节课程后，可以把课程包共享给同组教师或后续教学使用。共享的对象不是单个页面或单个代码文件，而是一套包含任务情境、积木化实验、代码实践和素材关系的课程包。这样，其他教师拿到资源后，不需要重新猜测课程设计意图，也能较快理解课程如何进入、如何操作、如何复盘。

#### 4. 课程上传与发布

课程上传与发布功能用于把本地课程成果转化为可分发资源。当课程经过课堂验证和修改后，可以被整理为更稳定的版本进行上传或发布。上传发布的意义在于让课程资源从个人备课材料进入更大的资源池，也让学校或教研组能够形成可持续积累的人工智能课程库。

#### 5. 课程拉取更新

课程拉取更新功能用于支持课程持续迭代。人工智能课程内容变化快，实验资源也可能随着工具版本、模型能力或教学目标发生调整。平台需要支持课程资源的拉取更新，使教师可以获取最新课程包，也可以在已有课程基础上继续修订。这样，课程资源不再是一次性文件，而是可以持续更新的教学资产。

#### 6. 课程协同共建与复用

课程协同共建与复用功能用于支持教研团队共同建设课程。一位教师可以先完成基础实验链路，另一位教师可以补充拓展任务，第三位教师可以整理评价问题或替换更适合学生的素材。通过协同共建，课程资源逐渐从个人材料升级为团队资源。通过复用，课程包可以在不同班级、不同课次、不同学段中持续使用，并根据反馈不断优化。

#### 7. 课堂课程包分发

课堂课程包分发功能用于把课程建设成果真正带入课堂。课程包分发不是简单复制文件，而是将讲解页、`XEdu Pro` Blockly 工作区、Notebook、脚本、素材和说明文档以完整结构交付给课堂使用环境。分发后的课程包可以直接成为课堂实验入口，学生可以沿着既定路径完成体验、理解、实践和复盘，教师也可以减少临时配置和重复说明。

课程资源共享平台功能的价值在于把人工智能课程建设从“临时准备一节课”推进到“持续建设一套资源”。课程创建与导入解决资源进入平台的问题，资源组织与管理解决资源结构清晰的问题，共享和发布解决资源流转的问题，拉取更新解决资源持续迭代的问题，协同共建解决团队共同建设的问题，课堂课程包分发则解决资源如何落地到真实课堂的问题。

## 三、应用过程与效果

在实际应用中，平台已围绕人工智能课堂实验开展试用，服务 `30` 名学生，覆盖 `12` 节课。课堂实施时，教师先通过课程资源准备讲解体验页面、`XEdu Pro` Blockly 工作区、Notebook 和实验素材，学生进入统一工作台后，按照“体验 - 理解 - 实践 - 应用”的路径完成学习任务。

实验平台的典型应用过程可以概括为“课程准备 - 课堂进入 - 情境体验 - 可视化实验 - 代码实践 - 结果复盘 - 继续学习”。课前，教师整理课程包，确认讲解页、Blockly 工作区、Notebook、脚本和素材文件能够正常打开。课中，学生从统一入口进入课程，先通过讲解页理解任务，再通过 `XEdu Pro` Blockly 观察和操作人工智能流程，随后进入 Jupyter Notebook 运行代码、修改参数、查看输出。课后，教师根据学生操作情况和课堂反馈继续调整课程包。

以“运动会上的 AI 裁判”等课堂任务为例，学生能够围绕运动场景中的识别、判断和结果反馈等问题理解人工智能的应用过程。低年级学生可以侧重任务情境和积木操作，基础较好的学生可以进一步进入代码实验和结果分析。这样的安排使同一平台可以支撑不同学习起点的学生，也方便教师根据课时安排和学段目标灵活选择教学深度。

从实验平台应用效果看，平台主要带来了三方面改进。第一，降低了课堂实验实施门槛。学生不需要在多个工具之间来回跳转，教师也不需要反复说明文件位置和环境入口，课堂可以更快进入学习任务。第二，增强了学习过程连续性。讲解、流程、代码和结果被组织在同一任务链路中，学生更容易保持对任务的整体理解。第三，增强了学生表达和复盘的依据。运行结果、流程截图和 Notebook 输出可以成为课堂讨论的学习证据。

从课程资源共享应用过程看，平台将人工智能实验所需的讲解页、Notebook、`XEdu Pro` Blockly 工作区、脚本、素材和结果文件组织为可复用课程包。教师可以在课前完成资源整理，在课堂中直接调用，在课后根据学生反馈继续修订。这样一来，课程资源不再停留在单次课堂使用，而是可以持续沉淀、反复使用和逐步优化。

课程资源共享带来的效果主要体现在四方面。第一，提升了资源复用效率，同一课程包可以在不同班级、不同课次中继续使用。第二，支持了课程共建，教师可以围绕已有课程包进行补充、修订和再发布，形成更稳定的校本人工智能课程资源。第三，增强了推广可能性，结构化资源包能够更清楚地呈现课程目标、实验路径、代码实践和素材关系，便于其他教师理解和迁移。第四，减少了课堂准备中的重复劳动，使教师可以把更多精力投入任务设计、问题引导和学生反馈。

目前，配套资源中已形成课程页面、`XEdu Pro` Blockly 工作流、Notebook 代码、样例运行结果、课程包结构和课程共建机制等证据材料。这些材料能够说明平台不是停留在概念设计层面，而是围绕真实课程内容形成了可运行、可展示、可复用的应用链条。

课程页面证据展示了平台如何承载任务情境和操作引导；`XEdu Pro` Blockly 工作流证据展示了人工智能任务如何被拆解为可视化流程；Notebook 与 Python 代码证据展示了实验如何进入真实代码实践；样例运行结果展示了输入、检测、处理和输出之间的关系；课程资源包结构展示了讲解页、工作区、代码、素材和输出如何共同组成一个课程单元；课程共建机制展示了资源如何被共享、修订和再次使用。

这些证据共同支撑了本案例的两个核心判断：第一，`XEdu Client` 具有实验平台属性，能够把讲解体验、`XEdu Pro` 积木化实验和 Jupyter 代码实践组织成连续学习路径；第二，`XEdu Client` 具有课程资源共享平台属性，能够把课堂实验材料沉淀为可管理、可迁移、可共建、可分发的课程资源包。

后续还需要进一步补充课堂照片、学生作品、教师使用反馈、学生学习记录和不同学段应用数据，形成更系统的课堂效果评价。现阶段的应用效果主要体现为课堂实施更顺畅、学习路径更连续、课程资源更容易沉淀和共享。随着更多课程样例和更多应用场景加入，平台的评价也将从可用性评价进一步走向学习成效评价和课程推广评价。

## 四、创新与反思

本案例的创新首先体现在实验平台链路的重构。平台不再把讲解、积木、代码和结果展示割裂为多个独立环节，而是围绕“体验、理解、实践、应用”构建连续的课堂学习路径。学生能够先从情境进入，再通过 `XEdu Pro` Blockly 理解流程和模型能力，最后进入 Jupyter 完成代码实践和结果分析。

这种创新的关键不在于单独使用了某一种工具，而在于形成了 `XEdu Client + XEdu Pro + Jupyter + 课程资源` 的组合拳，并重新组织了人工智能实验课的学习顺序。传统做法中，学生可能先面对代码，也可能只看到演示结果，学习过程容易在“看热闹”和“看不懂”之间摇摆。平台把任务情境、`XEdu Pro` 可视化实验封装和 Jupyter 代码实践组合起来，使学生能够逐步接近人工智能任务的真实结构。

本案例的创新还体现在课程资源共享机制上。平台把人工智能实验材料从“零散文件”转化为“结构化课程包”。通过课程资源包，讲解页、`XEdu Pro` Blockly 工作区、Notebook、Python 脚本、图片素材和说明文档可以被放在同一课程结构中管理。这样的组织方式让课程资源更容易被理解、复制、修改和共享，也为学校持续建设人工智能课程资源库提供了基础。

从学校课程建设角度看，结构化资源包能够帮助教研组形成共同语言。教师讨论的不再只是某个文件能不能打开，而是课程目标是否清楚、实验路径是否顺畅、`XEdu Pro` Blockly 与 Jupyter 是否衔接、素材是否适合学生、结果是否便于复盘、课程包是否便于共享和更新。平台因此也成为课程教研和资源共享的支撑工具。

生成式人工智能的引入是本案例的重要特征。`DeepSeek` 在项目中承担了需求梳理、问题分析、测试整理和文稿优化等辅助工作，帮助教师团队更高效地完成教育工具开发和申报材料整理。需要强调的是，AI 并不替代教师的教学判断，而是帮助教师更快整理问题、形成方案和完善表达，最终仍由教师结合课堂经验进行选择、修订和落实。

从正向价值看，AI 帮助团队提升了问题归纳和材料整理效率。教师可以把课堂中的真实问题描述给 AI，请其从功能模块、测试风险、表达结构等角度提出建议，再由教师进行筛选。这样的过程让教师不必从空白处开始整理，也能更快发现自己可能遗漏的检查角度。

从使用边界看，AI 生成内容必须经过人工校验。特别是在教育案例申报中，不能因为 AI 表述流畅就直接采用夸大性结论，也不能把尚未真实验证的功能写成确定成果。因此，本报告在表述中尽量保持边界清楚，把已形成的功能、已准备的证据和后续需要补充的数据区分开来。

项目仍有继续完善空间。一是需要进一步积累不同学校、不同学段的应用数据，形成更系统的课堂效果评价；二是需要继续优化安装部署和运行维护体验，降低普通教师独立使用的门槛；三是需要丰富更多可直接导入的课程样例，形成面向基础教育人工智能课程的资源库；四是可以进一步完善课程资源版本管理和共享流程，使课程包的共建、修改、发布更加规范。

总体来看，`XEdu Client` 不是单一课件或单次演示程序，而是一款面向基础教育人工智能课堂真实需求开发的一体化实验与课程资源共享平台。它既关注学生如何从体验走向理解、从实践走向应用，也关注教师如何稳定组织课堂、沉淀课程资源并实现共享复用，具有较强的课堂适用性和推广价值。
