# 创AI案例开发与应用报告送审版

案例名称：`XEdu Client：面向人工智能课堂的一体化实验学习平台`

作者：`王海涛`

单位：`上海科技大学附属学校`

## 一、开发背景

随着人工智能课程逐步进入基础教育课堂，学校在开展相关教学时面临的主要困难，已经不只是“有没有实验内容”，而是“能不能稳定、连续、可复用地组织课堂实验”。在真实教学中，教师往往需要同时准备讲解材料、实验素材、可视化流程、代码环境、运行结果和课堂展示内容；学生则需要在任务理解、流程观察、代码实践和结果复盘之间不断切换。如果这些环节分散在不同软件和不同目录中，就容易出现环境配置复杂、课堂切换频繁、学习路径割裂、课程资源难以沉淀等问题。

从学生学习过程看，人工智能课程既需要低门槛入口，也需要逐步过渡到真实的代码实验。仅使用静态课件或结果演示，学生容易停留在“看到了效果”而没有真正理解任务流程；直接进入完整代码环境，又容易因文件路径、依赖环境和运行报错耗费大量课堂时间。尤其在初中阶段，学生更需要一个能够承接“先理解任务，再观察流程，最后进入代码实践”的连续学习空间。

从教师实施过程看，人工智能课程资源也不应停留在一次性文件层面。一节课通常会涉及 HTML 讲解页、Blockly 工作区、Jupyter Notebook、Python 脚本、图片素材、结果文件等多类资源。若缺少统一工作台和结构化资源组织方式，教师每次上课都需要重复整理入口、说明路径和排查环境问题，优质课程也难以在不同班级、不同教师之间持续复用与更新。

基于上述课堂需求，我们开发了 `XEdu Client`。该项目以桌面端工作台为统一入口，整合课程资源管理、Blockly 可视化理解、Jupyter 代码实践、本地运行支撑等能力，帮助学生在同一任务情境中连续完成体验、理解、实践和复盘，也帮助教师降低课堂组织成本，提高人工智能实验课程的稳定性与复用效率。

在开发与材料整理过程中，团队还引入了国产生成式人工智能工具 `DeepSeek` 进行辅助，主要用于问题梳理、测试清单整理、申报文稿打磨等环节。生成式人工智能在本案例中承担的是辅助性角色，最终的教学判断、功能取舍和申报表述仍由教师团队结合真实课堂需求完成。

## 二、设计与开发

### （一）平台/技术选择

`XEdu Client` 采用“桌面端入口 + 本地服务支撑 + 课程资源结构化管理”的总体技术路线。桌面端基于 `Electron` 构建统一工作台，前端使用 `Vite` 与原生 `HTML/CSS/JavaScript` 组织界面交互，后端使用 `Flask + Python` 提供资源读取、运行装配、接口服务与 Jupyter 管理能力。代码实践部分由 `Jupyter Notebook` 承接，可视化理解部分基于 `Blockly` 组织课堂流程，课程实验能力则结合 `XEduHub` 等工具进行调用和扩展。

这种技术选择并不是对现有工具的简单拼接，而是围绕课堂实验链路进行重组。项目希望解决的不是某一项单点能力，而是学生如何在统一工作台中从“看到任务”逐步走向“理解流程”和“继续代码实验”，教师如何把分散的教学资源组织成可进入、可复用、可维护的课程包。因此，项目特别强调本地部署、低网络依赖和课程资源结构化管理，适合学校机房、普通教室和校本人工智能课程场景使用。

从仓库实现看，项目已形成较清晰的分层结构：`electron/main/main.js` 负责桌面宿主与进程编排，`renderer/` 负责前端交互与学习入口，`backend/api/app.py` 与各路由模块负责接口装配，`backend/services/jupyter_service.py`、`backend/services/blockly_xeduhub_support.py` 等服务模块负责核心业务能力。这种结构为后续课程扩展、运行维护和课堂应用提供了稳定基础。

### （二）开发过程

项目开发首先从真实课堂问题出发，明确平台不是单纯的 Notebook 启动器，也不是单独的 Blockly 页面，而是服务人工智能课堂连续实施的实验学习平台。团队围绕“学生进入课堂后继续完成实验”这一核心目标，逐步梳理出平台需要支撑的四类能力：统一实验入口、连续学习路径、课堂运行稳定性和课程资源复用机制。

在学习路径设计上，项目采用“讲解体验 - 流程理解 - 代码实践 - 结果复盘”的组织思路。以仓库中的 `courses/ai-showcase-exam-2025/01_目标检测与细粒度分类/` 样例为例，学生可以先打开 `index.html` 理解任务场景，再通过 Blockly 观察“检测 - 裁剪 - 分类”的流程，最后进入 `detection_and_classification.ipynb` 或对应 Python 脚本继续代码实验。这样，学生看到的不再是孤立文件，而是一条可连续推进的课堂任务链路。

在课程资源建设上，项目把 HTML 页面、Notebook、Python、Blockly 工作区、图片素材等内容组织为结构化课程目录，便于教师围绕同一主题持续维护课程。根据仓库文档与测试说明，系统已支持课程创建、导入、资源读取、课堂接入、课程上传与拉取更新等流程，说明该项目已超出单次演示程序范畴，具备平台化资源管理特征。

在开发质量保障方面，项目通过脚本与测试对高风险能力进行验证。例如，仓库中提供了 `npm run test:blockly-runtime`、`npm run build` 等前端验证命令，也包含 `backend/tests/test_blockly_resources_api.py`、`backend/tests/test_blockly_xeduhub_support.py`、`backend/tests/test_ai_routing_api.py` 等测试文件，用于检查 Blockly 运行时、资源接口和 AI 路由等关键能力。这些实现与文档共同说明，项目在开发阶段已关注课堂稳定性、资源加载和运行安全等问题。

在 AI 辅助开发方面，团队采用“问题明确、约束清晰、结果可落地”的方式使用 `DeepSeek`。例如，在问题分析与测试整理阶段，可通过提示词要求 AI 从课堂稳定性、资源加载、学生操作路径等角度输出风险项与检查清单；在申报材料整理阶段，则要求 AI 保持原意、不夸大事实、突出课堂连续性与工具一体化。AI 输出仅作为辅助草案，教师团队会结合真实项目结构、课堂目标和申报规则进行筛选、改写与校正。

### （三）功能架构

围绕课堂实验全过程，项目当前形成了五个相互支撑的功能模块。

第一，统一学习入口模块。平台以桌面端工作台为入口，学生和教师可以从同一界面进入课程资源、Blockly 实验和 Jupyter Notebook，减少课堂中反复查找文件、切换软件和确认路径的时间成本。

第二，讲解体验与任务导入模块。课程中的 HTML 页面用于承载任务情境、实验说明和学习引导，帮助学生先理解“本节课要解决什么问题”，为后续可视化流程观察和代码实践建立背景。

第三，Blockly 可视化理解模块。学生通过积木化方式观察人工智能实验的主要流程，理解输入、处理、模型调用、结果输出之间的关系。该模块尤其适合初学者建立对 AI 任务链条的整体认识。

第四，Jupyter 代码实践模块。学生在理解任务情境和流程后，可以进入 Notebook 运行、阅读和修改代码，进一步观察参数变化、结果反馈和实验逻辑，从而把可视化理解过渡到真实代码实践。

第五，课程资源管理与共享模块。教师可以围绕一门课组织讲解页、Notebook、Blockly 文件、脚本和素材，并通过导入、本地保存、课堂接入、上传与拉取更新等能力，逐步形成可沉淀、可复用、可共享的课程资源包。

这五个模块共同服务于同一教学目标：让学生在统一任务情境中持续学习，让教师在稳定工具环境中组织课堂，让课程资源在真实教学中不断积累和迭代。

## 三、应用过程与效果

目前，项目已经具备面向人工智能课堂开展实验教学的基本条件，并形成了较完整的课程样例、运行说明、测试说明和申报材料基础。结合仓库中的课程结构与测试文档，平台可以支持以下典型应用流程：教师课前准备课程资源并组织实验入口，学生课堂中先通过讲解页理解任务，再通过 Blockly 观察流程，随后进入 Jupyter 继续代码实践，最后围绕输出结果进行展示、讨论和复盘。

以 `01_目标检测与细粒度分类` 为例，学生能够围绕图像识别任务理解“检测框定位目标 - 裁剪图像区域 - 继续做细粒度分类”的完整实验过程。对于基础较弱的学生，可以更多停留在任务体验和流程观察层面；对于基础较好的学生，则可以继续进入 Notebook 修改参数、观察结果并完成拓展任务。这种设计有利于同一平台适配不同学习基础和不同课时深度。

从平台价值看，项目在课堂应用中预期能够带来三方面效果。第一，降低实施门槛。学生不必在多个系统之间频繁切换，教师也不需要反复解释文件位置和实验入口。第二，增强学习连续性。讲解、流程、代码和结果在同一任务链路中组织，学生更容易建立对人工智能实验全过程的整体理解。第三，提高资源复用效率。课程材料可以按结构化方式沉淀为课程包，方便在不同班级、不同教师和后续课程中继续使用。

正式提交前，本节建议补充真实应用证据，并统一替换以下字段：`[应用学校]`、`[实施班级数]`、`[学生人数]`、`[实施课时数]`、`[课堂照片]`、`[学生作品截图]`、`[教师反馈摘录]`、`[学生反馈摘录]`。若后续需要申报评审或答辩展示，还可补充课堂前后对比、学生作品样例和教师教研复盘记录，以增强案例说服力。

## 四、创新与反思

本案例的创新主要体现在四个方面。

第一，围绕课堂实验链路重组工具关系。项目没有把讲解页、Blockly、Jupyter 当作彼此独立的工具，而是围绕“体验、理解、实践、复盘”构建统一的实验学习路径，使课堂实验从分散操作转向连续任务。

第二，突出初中人工智能课堂的低门槛与可进阶。平台既保留了 Blockly 的可视化入口，又提供了 Jupyter 的代码实践空间，能够帮助学生从任务体验逐步过渡到流程理解和代码应用，更符合初中阶段人工智能课程的学习节奏。

第三，把课程资源从零散文件提升为可维护课程包。项目不仅关注学生能否完成一次实验，也关注教师如何长期维护课程、分享课程和更新课程，这使平台具备了更强的课堂适用性与推广潜力。

第四，引入生成式人工智能辅助开发与材料整理。`DeepSeek` 在本项目中被用于问题梳理、测试整理和文稿辅助，使教师团队能够更高效地完成教育工具开发与申报准备。与此同时，项目坚持“AI 辅助、人来定稿”的原则，避免将 AI 输出直接替代真实教学判断。

当然，项目仍有进一步完善空间。一是需要继续补充真实课堂应用数据，形成更完整的效果证据链；二是需要继续优化安装部署和环境维护体验，降低普通教师独立使用门槛；三是可以进一步扩展更多可直接导入的课程样例，逐步形成覆盖不同主题和不同学段的人工智能实验资源库。

总体来看，`XEdu Client` 不只是单一课件或演示程序，而是一款面向基础教育人工智能课堂真实需求开发的一体化实验学习平台。它既关注学生如何从体验走向理解、从实践走向应用，也关注教师如何稳定组织课堂、沉淀资源并实现共享复用，具有较好的课堂应用价值和推广潜力。
