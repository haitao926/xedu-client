# 创AI论文级图体系设计

本文件用于定义 `XEdu Client` 申报与论文共用的核心图体系。目标不是“做几张好看的示意图”，而是形成一组能够清晰表达系统定位、核心机制与教学价值的结构图。

## 总体原则

- 图的作用优先于风格：每张图必须回答一个明确问题。
- 图内信息结构优先清晰，再考虑视觉效果。
- 优先使用：编号、分区、短标签、箭头、层级、留白。
- 图中尽量避免长段文字，正文解释放在图注或段落中。
- AI 生成图可以用于结构底图，但最终图应经过人工补标注或排版整理。

## 图 A：项目总体架构图

### 用途

- 用于说明 `XEdu Client` 不是单一实验工具，而是更像平台的教学实验系统。
- 放在报告“设计与开发”开头或“功能架构”部分。

### 核心回答的问题

- 系统由哪些层组成？
- 桌面宿主、前端、后端、实验环境、课程仓库和工具箱之间是什么关系？

### 图内结构

- 最上层：`教师` / `学生`
- 平台宿主层：`Electron`
- 前端工作台层：`HTML体验` / `Blockly实践` / `Jupyter应用创新`
- 后端服务层：`课程资源` / `课堂接入` / `同步更新` / `AI助教`
- 实验能力层：`XEduHub 工具箱`
- 外部资源层：`本地课程目录` / `云端课程仓库(Gitea)` / `模型与数据资源`

### 建议标签

- `桌面宿主`
- `教学工作台`
- `服务层`
- `能力工具箱`
- `课程与资源层`

## 图 B：核心问题到解决路径映射图

### 用途

- 用于报告背景与项目价值说明。
- 帮助评审快速理解“项目为什么要做”。

### 核心回答的问题

- 这个项目到底在解决哪些真实问题？
- 每类问题分别由哪类平台能力来回应？

### 图内结构

- 左侧四类问题：
  1. `实验环境问题`
  2. `学习路径断裂问题`
  3. `AI实验能力分散问题`
  4. `课程共享与更新问题`
- 右侧四类解决路径：
  1. `环境承载与统一入口`
  2. `HTML—Blockly—Jupyter 学习主线`
  3. `XEduHub 完整工具箱`
  4. `教师课程分享与更新机制`
- 中间用箭头一一对应，也可允许一对多映射。

### 建议标签

- `问题`
- `平台回应`
- `对应机制`

## 图 C：HTML—Blockly—Jupyter 学习主线图

### 用途

- 用于突出项目最核心的教学创新。
- 适合放在“平台/技术选择”或“创新点”附近。

### 核心回答的问题

- 为什么项目不是三个入口并列？
- 学生的学习过程是如何连续推进的？

### 图内结构

- 从左到右三阶段：
  1. `HTML（体验）`
  2. `Blockly（实践）`
  3. `Jupyter（应用创新）`
- 每个阶段下面放一句短说明：
  - `任务感知`
  - `流程理解`
  - `代码扩展与创新`
- 用清晰箭头连接，强调 progression。

### 建议标签

- `体验`
- `实践`
- `应用创新`
- `连续学习主线`

## 图 D：XEduHub 工具箱支撑图

### 用途

- 用于说明 XEduHub 在系统中的角色不是附属模块，而是能力底座。
- 适合放在“功能架构”或“核心创新”部分。

### 核心回答的问题

- XEduHub 究竟支撑了什么？
- 它和 Blockly / Jupyter 的关系是什么？

### 图内结构

- 中心：`XEduHub`
- 向外发散到四类能力：
  - `图像与输入资源`
  - `模型调用与任务执行`
  - `流程组织与运行`
  - `结果展示与反馈`
- 左侧连接 `Blockly`
- 右侧连接 `Jupyter`
- 下方可连接 `课程实验样例`

### 建议标签

- `完整工具箱`
- `统一能力底座`
- `运行支撑`

## 图 E：教师课程分享与更新机制图

### 用途

- 用于说明“更像平台”的关键闭环。
- 适合放在“应用过程与效果”或“创新点”部分。

### 核心回答的问题

- 教师如何创建、分享、更新课程？
- 为什么这个项目不是静态资源包，而是动态课程平台？

### 图内结构

- 环形或流程式结构：
  1. `本地创建课程`
  2. `导入/整理课节与实验`
  3. `上传课程`
  4. `课堂使用`
  5. `课后修订`
  6. `拉取更新 / 再分享`
- 用一句话点明：`上一节、改一节、同步一节`

### 建议标签

- `课程分享`
- `持续更新`
- `教师协作`
- `动态课程资源`

## 图 F：典型课堂应用流程图

### 用途

- 用于“应用过程与效果”部分。
- 让评审看到一节课是怎么落地的。

### 核心回答的问题

- 教师和学生分别如何使用这个平台？
- 课堂中的关键行为顺序是什么？

### 图内结构

- 从左到右 6 步：
  1. `教师备课`
  2. `开启课堂`
  3. `学生进入当前实验`
  4. `Blockly 理解流程`
  5. `Jupyter 实践与修改`
  6. `结果复盘与课后更新`

### 建议标签

- `教师侧`
- `学生侧`
- `课堂进行`
- `课后迭代`

## 本轮建议优先级

优先定义并落地这三张：

1. `图 B：核心问题到解决路径映射图`
2. `图 C：HTML—Blockly—Jupyter 学习主线图`
3. `图 E：教师课程分享与更新机制图`

原因：

- 它们最直接回应“背景不清晰”和“平台定位不清晰”的问题。
- 即使暂时没有完全真实课堂数据，也可以先把项目逻辑讲清楚。
