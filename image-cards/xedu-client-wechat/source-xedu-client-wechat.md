# 公众号文章视觉源稿

## 核心立意

XEdu Client 从学生不会启动 Jupyter、误关运行终端导致课堂中断这一真实问题出发，逐步发展为面向人工智能教学的桌面实验工作台。项目要解决的不只是软件入口问题，而是让学生从交互体验、图形化理解自然过渡到真实代码实践，让教师能够稳定组织、重复实施并持续更新课程。

## 文章叙事

### 一切从一个被关掉的黑框开始

学生找不到 Jupyter 的启动入口，或顺手关掉承载服务的黑色终端窗口。教师不得不在机房逐台排查，课堂注意力从人工智能问题转移到环境故障。XEdu Client 最初希望提供一个更清楚的实验入口，统一呈现 Jupyter 的启动、停止和运行状态。

### 真正需要接起来的是体验和实践

人工智能概念可以先通过 HTML 互动页面形成直观经验，再进入 Jupyter 阅读代码、修改参数、训练模型并解释结果。核心路径是：先体验现象，再理解过程，最后进入真实代码实践。

### AI Coding 时代重新理解积木编程

当语法可以由人工智能辅助生成，编程教育更应关注问题拆解、数据流、模型选择、参数调整、结果验证和可靠性判断。Scratch 可以降低拼写、缩进和 API 记忆带来的干扰，让程序流程直接可见；Python 仍然重要，但不必成为每个学生理解人工智能的第一道门槛。

HTML、Scratch、Jupyter 是同一知识的不同入口，不要求每节课全部使用：

- HTML：快速操作、观察并形成直观经验。
- Scratch：让流程、逻辑和人工智能调用过程可见。
- Jupyter：进入真实代码，修改、运行并继续探究。

### XEdu Client 的产品回应

- 实验上不起来：统一管理 Python 解释器与 Jupyter 状态，内置 Scratch，并在课前检查环境和依赖。
- 学习连不起来：用课程包组织课节、HTML、Scratch、Notebook 和素材，让学生从同一课程任务进入实验。
- 课程留不下来：支持课程导入、校验、预览、备份、更新和发布，让课程可以继续修改和复用。

课堂模式负责课程发现、课程包与课程文件拉取、课堂索引和实验入口，不应画成完整作业管理或学习分析系统。

### 运动会 AI 裁判案例

学生先在 HTML 实验中调整神经网络层数和神经元数量，观察网络结构变化；随后进入 Notebook，读取数据，划分训练集和测试集，搭建 MLP，观察 Loss 下降并完成模型训练。此案例只有 HTML 和 Notebook，不应添加 Scratch 画面。

### 一节课的教师流程

- 课前：选择并测试 Python，导入课程包，打开本节实验预检。
- 课中：选择课节并开启课堂，先让一台学生机试连，再让全班进入。
- 课后：结束课堂并备份课程，需要时从远端更新或发布到 Gitea。

### 当前边界

- 教师版使用外置 Python 3.9+，不是完全零配置。
- Python 执行是本机高权限能力，不是云端沙箱。
- 课堂模式依赖可互访局域网。
- XEdu Client 负责课程导入、校验、运行、分发和更新；XEdu Teacher Skills 的课程智能创作能力另写专文。

### 结尾

XEdu Client 想做的，是让人工智能实验课从偶尔成功的展示，变成普通机房里可以稳定发生的学习。
