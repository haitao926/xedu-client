## Design Context

### Users
- Primary users are teachers and students using XEdu as a desktop teaching client.
- Their core job is to enter an experiment quickly, then move between visual programming and real Python practice with as little setup friction as possible.
- The interface should reduce startup anxiety and make experimentation feel immediate.

### Brand Personality
- Calm, capable, lab-like.
- The product should feel trustworthy, focused, and ready-to-run rather than busy, admin-heavy, or “management console” oriented.
- Emotionally, the UI should create confidence, momentum, and teaching clarity.

### Aesthetic Direction
- Platform-lab aesthetic: bright, clean, slightly futuristic, but restrained.
- Jupyter Lab and Blockly should read as first-class experiment environments, not as subordinate course subpages.
- Classroom and course surfaces should feel supportive and secondary: useful entry points, not the center of gravity.
- Avoid dashboard clutter, overexplaining system status, or visually overemphasizing provenance/context.

### Design Principles
1. Open-to-experiment first: the fastest visible action should always be entering an experiment environment.
2. Environment over administration: code workspaces should dominate; setup and course context should stay secondary.
3. Weak coupling in the UI: classroom/course relationships may exist, but they should be expressed lightly.
4. Clear duality: Blockly is the visual programming layer; Jupyter Lab is the code practice layer.
5. Calm confidence: clean hierarchy, low-noise copy, and obvious primary actions should guide the experience.
